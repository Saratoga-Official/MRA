# 安卓打包（MaaFwApp）

MRA 的安卓版通过 **[MaaFwApp](https://github.com/Aliothmoon/MaaFwApp)** 出包。MaaFwApp 是
MaaFramework 的通用 Android GUI，在**构建期**把一份 Project Interface V2 资源打进 APK，
运行时通过 [Shizuku](https://shizuku.rikka.app/) 或 root 起特权进程，截屏与点击走本机 native
controller，不经过 adb。

接入模型：MRA 只提供一份**打包配方** [`pi-profile.yaml`](../../pi-profile.yaml)（指明资源在哪、
包名/图标、agent 怎么拉起），MaaFwApp 照配方出 APK。换资源 = 改资源 + 重新出包，不改外壳代码。

> 资源随 APK 绑定，Android 端不支持热更新，也暂不支持 Mirror酱。

本接入参考了 [MAA1999/M9A](https://github.com/MAA1999/M9A) 的标准写法：配方用相对路径、
agent 运行时目录固定在仓库内，配方本身自洽，本地与 CI 共用同一份。

## 目录结构差异说明

M9A 的资源是扁平的（interface.json、resource/、agent/ 都在仓库根），配方可 `assets: ..` 直接
引用；MRA 的 PI 在 `assets/` 子目录，而 `agent/`、`LICENSE`、图标在仓库根，与 `assets/` 不同层。
MaaFwApp 的 `include` 只能引用 `assets` 目录内的相对路径，无法跨目录 `../agent`，因此出包前需把
`agent/`、`LICENSE` 拷进 `assets/`，并由 `logo.ico` 生成 `assets/logo.png`。这一步在
`.github/workflows/android.yml` 的 “Stage PI assets” 里完成。

## 自动出包（CI）

`.github/workflows/android.yml` 已完成全部接入：

1. 检出 MRA（含子模块）与 MaaFwApp（到 `Android/MaaFwApp`）
2. `python configure.py` 生成 OCR 模型，把 `agent/`、`LICENSE`、由 `logo.ico` 转出的
   `logo.png` 铺进 `assets/`，并把 `interface.json` 版本号替换成本次 tag
3. `scripts/setup_maa_framework.py` 铺 MaaFramework 的 Android `.so`
4. `scripts/build_agent_bundle.py` 基于 `agent/requirements.txt` 组装内嵌 Python 运行时
5. 按 `pi-profile.yaml` 出包，产物 `MRA-<tag>-android-<variant>.apk`

- push / PR 自动出 debug 包；手动 `workflow_dispatch` 可选 debug/release 与 MaaFramework tag
- 打 `v*` tag 时出 release 包并附到对应 Release
- debug 只出 arm64-v8a；release 出双 ABI（arm64-v8a + x86_64）

## 本地出包

需要 JDK 17、Android SDK、Python 3。

```bash
git clone --recursive https://github.com/Saratoga-Official/MRA.git
cd MRA

# 取外壳：作为子模块或直接 clone 到 Android/MaaFwApp 均可
git clone https://github.com/Aliothmoon/MaaFwApp.git Android/MaaFwApp

# 铺资源
python configure.py
cp -r agent assets/agent
cp LICENSE assets/LICENSE
magick "logo.ico[0]" assets/logo.png     # 需 ImageMagick；旧版用 convert

# 铺 MaaFramework .so 与 agent 运行时
cd Android/MaaFwApp
python scripts/setup_maa_framework.py --abi arm64-v8a --tag v5.14.1
python scripts/build_agent_bundle.py \
    --out "${PWD}/../../agent-dist" --abi arm64-v8a \
    --requirements "${PWD}/../../agent/requirements.txt"

# 指定配方与 ABI（写进 Android/MaaFwApp/local.properties，不进 git）
cat > local.properties <<EOF
sdk.dir=<你的 Android SDK 路径>
pi.profile=../../pi-profile.yaml
build.debugAbi=arm64-v8a
EOF

./gradlew :app:assembleDebug     # 或 installDebug 直接装到连接的设备
```

产物在 `Android/MaaFwApp/app/build/outputs/apk/`。改 `interface.json`、`resource/`、`agent/`
后重新 `assembleDebug` 即可；换了 `agent/requirements.txt` 再跑一遍 `build_agent_bundle.py`。
本地出 release 双 ABI 包时，`setup_maa_framework.py` 要用 `--abi all`、`build_agent_bundle.py`
要加 `--abi x86_64`，并把 `local.properties` 的 `build.debugAbi` 换成 `build.releaseAbi=arm64-v8a,x86_64`。

## Release 签名

默认 `assembleRelease` 出**未签名**包。配置签名后再出 release：在 MaaFwApp 的 `local.properties`
或环境变量提供 `KEYSTORE_PATH`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`。
CI 走仓库 Secrets：`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、
`ANDROID_KEY_PASSWORD`；未配置时 release 包未签名，日常用 debug 包即可。

## 版本说明

- MaaFramework Android `.so` 用 v5.14.1（≥ MaaFwApp 要求的最低 v5.13.0）。
- agent 内核自带 maa 5.14 的 Python 绑定，会覆盖 `agent/requirements.txt` 里桌面端的
  `MaaFw==5.10.2` pin，这是 `build_agent_bundle.py` 的预期行为（公开索引无 Android 版 maafw 轮子）。
- `interface.json` 图标为 `logo.ico`，Android 不解码 ico，launcher 图标改用转出的 `logo.png`。

## 常见问题

| 现象 | 排查 |
|:---|:---|
| 一点开始就 native 加载失败 | `setup_maa_framework.py` 未跑或 ABI 不符 |
| 开始任务提示未带 agent 运行时 | agent bundle 未打进，检查 `agent-dist` 与 ABI 是否对齐 |
| 换了资源装上还是旧内容 | 清应用数据；版本号未变时可能沿用旧解包 |
| 查看运行日志 | `adb logcat -s MaaFw` |
